# Experimental K6/K8 fused MoE

This path supports Qwen routed experts with K6 weights and shared experts
with K8 weights. All projections must use the mul1 codebook.
The default remains disabled. Rebuild the extension before use.

Set these variables before you start the server:

```sh
export EXL3_MOE_FUSED=1
export EXL3_MOE_FUSED_LAYOUT=native
export EXL3_MOE_FUSED9=1441792
export EXL3_MOE_FUSED_K6S8=1
```

Only the native six-stage variant is supported. Timing and other variants
are excluded. Without this setting, the existing fallback remains in use.
No model conversion is required.

## Checks

Run the CPU checks from the repository root:

```sh
python -m pytest --noconftest -q tests/test_moe_fused_k8_cpu.py tests/test_moe_fused_k6_cpu.py tests/test_moe_k56_cpu.py
```

On an idle ROCm GPU, run the real-weight check with the model directory:

```sh
python tools/qwen/check_k6k8_layers.py --model "$MODEL_DIR"
```

The GPU check loads one block at a time. It does not stop services.
It checks buffer bounds, finite outputs, repeatability, batch shape,
and error against the unfused path. Exit code 2 reports numerical differences.
It does not establish full-model quality or long-context correctness.

## Earlier hardware results

The prototype was tested on an EVO-X2 with 128 GB RAM and gfx1151.
The local Qwen3.8 Flash-Next EXL3 pack was labelled 6.05 bpw.
These results used base commit 7844feb. They are not a GPU test of the
rebased PR. Each comparison used the same experimental binary and changed
EXL3_MOE_FUSED_K6S8 from 0 to 1. Context was 262144, cache was 16-bit,
sessions was 2, and ndt was 3. The ngram table used disk streaming.

| Prompt | Before (tokens/s) | After (tokens/s) |
| --- | ---: | ---: |
| Explanation | 16.08 | 18.45 |
| Code | 21.71 | 25.67 |
| Story | 13.95 | 16.29 |

These are medians from two repetitions. Paired-request wall time changed
from 16.80 s to 15.79 s. These are small-sample observations.

All 64 real-weight half-layer comparisons had numerical differences.
Relative update RMS error ranged from 0.0149% to 0.0347%.
Bounds, finite-output, repeatability, and batch-shape checks passed.
The 128-token output checks matched. A 256-token code response differed
at token 204 in both repetitions. Its AST matched, but its text did not.
The largest shared top-10 probability change was 6.411 percentage points.
The cause of these differences remains unresolved.

Keep this path experimental until maintainers accept the numerical error
and repeat the GPU checks and full-model benchmarks on the PR revision.
Use tools/bench.sh with the same machine and command for each comparison.
